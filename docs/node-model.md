# 节点模型

## 1. 节点是什么

节点是 BusAgent 中具备稳定身份、清晰能力契约和独立生命周期的处理单元。它可以调用模型，也可以完全不使用模型。节点的价值来自职责边界，而不是进程数量。

以下能力都可以成为节点：

- 语音转文字、自然语言交互和语音合成；
- 任务规划、计划校验和结果聚合；
- 目标检测、场景理解、姿态估计和目标指认；
- 机械臂动作协调、碰撞处理和应急响应；
- 天气、搜索、数据库等通用工具；
- 监督、权限判断和人工确认；
- 上下文检索、压缩与持久化。

## 2. 节点契约

每个节点必须声明：

| 类别 | 必要内容 |
| --- | --- |
| 身份 | 节点名、实例 ID、版本和所有者。 |
| 能力 | 能处理的消息类型、内容版本与能力标签。 |
| 输入 | 必需字段、可选字段、最大大小和上下文要求。 |
| 输出 | 结果类型、可能事件、下一跳建议格式。 |
| 流式 | 是否支持流式输入、输出、提交与取消。 |
| 并发 | 并行度、顺序作用域、批处理和资源约束。 |
| 可靠性 | 超时、重试、幂等、恢复和健康检查。 |
| 安全 | 权限、数据级别、允许的副作用和人工确认条件。 |
| 观测 | 必需指标、日志、trace 和决策摘要。 |

未声明的能力默认不支持，未声明的权限默认不授予。

## 3. 并发模式

### 无状态并行

同一实例可以同时处理多个互不相关的输入，适合文本分类、检索或独立感知任务。节点仍需传播消息关联信息。

### 分区有序

不同分区可以并行，同一分区严格按序。例如，对话节点可同时处理不同会话，但同一会话的播报顺序必须稳定。

### 单资源串行

节点一次只执行一个占用独占资源的任务，例如单机械臂执行器。排队、优先级和抢占由明确的资源策略控制。

### 窗口聚合

节点在有限时间或数量窗口内收集多条消息后统一处理，例如规划节点聚合多个感知结果。输出必须记录使用的所有输入引用。

### 流式流水线

节点边接收边处理并继续产生分片，例如语言生成连接语音合成。节点必须声明背压、分片顺序、提交与中断语义。

一个节点可以组合多种模式，但组合方式必须体现在能力注册中。

## 4. 下一跳决策

节点可以根据输入、提示词和已声明策略给出下一跳建议。建议至少包含：

- 目标节点、主题或能力；
- 要发送的消息类型；
- 做出选择的结构化理由；
- 使用的条件与置信度；
- 失败或低置信度时的备选目标；
- 是否需要监督或人工确认。

为了避免自然语言路由失控，目标必须来自允许列表或能力注册表。节点不得通过在正文中写入地址来绕过结构化路由和权限检查。

## 5. Agent 节点与确定性节点

Agent 节点擅长语义理解、计划生成和开放条件判断，但输出不具备天然确定性。确定性节点适合状态机、权限校验、几何约束和硬件控制。

推荐组合方式是：

- Agent 节点提出意图、计划或候选动作；
- 确定性节点验证结构、资源与安全边界；
- 执行节点只接受经过验证并带执行凭证的命令；
- 结果作为事实事件返回，而不是由 Agent 猜测成功状态。

## 6. 生命周期

节点实例通常经历注册、就绪、降级、排空、离线和注销状态。升级时，新旧版本可以短暂并存，但同一任务是否允许跨版本执行必须由策略明确规定。

健康检查只说明节点是否可接收工作，不代表它最近的语义决策质量。模型节点还需要监测工具调用成功率、结构化输出有效率、延迟和监督拒绝率。

## 7. 提示词与策略版本

提示词、模型参数、工具清单和路由策略都是节点行为的一部分，应作为可追踪版本管理。一次决策至少记录所用版本标识，而非默认记录所有敏感原文。

监督节点可以建议调整上下文或提示词，但任何动态变更都应：

- 受允许范围限制；
- 关联触发原因和生效范围；
- 可撤销并可对比效果；
- 不扩大节点权限；
- 不在任务中途无记录地改变安全策略。

## 8. 节点设计检查表

新增节点前应回答：

- 它是否拥有单一、清晰且可测试的职责？
- 输入输出能否用稳定契约描述？
- 哪些工作可并行，哪些必须按哪个作用域排序？
- 它是否产生副作用，重复消息会发生什么？
- 下游变慢或离线时如何处理？
- 低置信度、超时和部分结果如何表达？
- 需要哪些上下文，是否包含敏感数据？
- 哪些路由或动作需要监督与人工确认？
- 如何衡量它比合并到已有节点更有价值？
