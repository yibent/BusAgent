# ADR-0001：采用总线式多智能体架构

- 状态：提议
- 日期：2026-08-07
- 决策者：BusAgent 维护者（待确认）

## 背景

机械臂的人机交互任务通常同时包含语音转写、语义理解、任务规划、自然语言反馈、视觉感知和物理执行。传统单主 Agent 架构往往让一个模型持有大部分上下文并串行决定每次工具调用。

这种结构在早期简单，但会让首次语音反馈等待规划，让感知等待对话，或让主模型复述已经生成的内容后才交给下游。多条任务同时到达时，主 Agent 还需要独自维护任务身份、资源冲突和执行顺序。

与此同时，小模型和专用模型的结构化输出、工具调用和局部决策能力已经足以承载受约束的专职节点。成熟的消息与机器人中间件也为解耦通信提供了基础。

## 决策

BusAgent 采用总线式架构作为核心方向：

- 将规划、对话、感知、执行和监督拆分为职责明确的节点；
- 让节点通过统一消息信封交换信息；
- 允许节点在受限目标集合中建议下一跳；
- 由总线维护身份、因果关系、顺序作用域、背压和取消；
- 通过上下文引用按需装配节点输入；
- 对高风险路由与动作实施分层监督；
- 对可并行和可流式的工作尽早启动，对独占资源保持显式串行。

该决策定义逻辑架构，不要求自行实现底层消息代理，也不替代 ROS 2 或硬件安全控制器。

## 预期收益

- 降低首次用户反馈和首个任务步骤的延迟；
- 减少单一主模型的上下文与工具协调负担；
- 允许不同能力独立扩展、替换和部署；
- 更清晰地表达并行任务与串行资源之间的关系；
- 提供节点级权限、观测与故障隔离边界。

## 代价与风险

- 分布式消息、版本、重试和状态一致性更复杂；
- 节点自主路由可能形成循环、越权或局部最优决策；
- 监督节点可能成为新瓶颈；
- 流式输出产生不可撤回副作用时需要明确提交边界；
- 端到端调试需要完整 trace 和上下文版本记录；
- 多模型调用的总成本不一定天然低于单主 Agent。

## 备选方案

### 单主 Agent 加工具调用

优点是实现简单、上下文集中。缺点是串行依赖强、主模型负担重，难以自然表达多任务并行和硬件资源约束。它仍将作为原型基线，用于衡量 BusAgent 是否真的带来收益。

### 固定工作流或 DAG

优点是可预测、易测试。缺点是对开放语言意图和运行时分支适应有限。BusAgent 会吸收其任务依赖和状态机思想，但允许受约束的语义路由。

### 纯事件驱动微服务

优点是成熟可靠。其本身不定义模型节点如何使用上下文、建议下一跳和接受监督。BusAgent 可构建在该基础设施之上，并补充 Agent 语义契约。

## 验证方式

本决策保持“提议”状态，直到完成与单主 Agent 基线的对照实验。至少比较：

- 首次可播放语音分片延迟；
- 首个感知或执行准备动作的启动延迟；
- 并发指令下的串线和乱序错误；
- 任务成功率与用户纠正次数；
- 模型调用、token 和基础设施成本；
- 故障定位和完整回放能力。

如果架构复杂度没有换来可测收益，应缩小总线职责或回退到更简单的工作流模型。
