# 监督与安全

## 1. 监督节点的定位

监督节点检查关键决策是否符合协议、权限、风险和任务策略。它不负责重新完成所有规划，也不应成为每条低风险消息的同步瓶颈。

适合监督的决策包括：

- 节点建议了未注册或未授权的下一跳；
- 请求访问新的敏感上下文；
- 模型生成了带物理副作用的候选动作；
- 感知置信度不足但计划仍准备继续；
- 任务之间发生资源、优先级或安全冲突；
- 节点连续失败、偏离计划或出现异常循环；
- 动态提示词、工具清单或路由策略将被修改。

## 2. 监督结果

监督结果应结构化为：

- **允许**：原建议可以继续；
- **拒绝**：违反硬性规则，不允许继续；
- **替换**：使用明确的安全目标或降级路径；
- **要求补充**：需要更多感知、状态或上下文；
- **要求人工确认**：等待用户或操作员决定；
- **隔离**：暂停异常节点或任务，保留诊断信息。

每个结果都记录适用规则、证据引用、有效范围和过期时间。

## 3. 分层监督

不是所有消息都需要调用模型监督。推荐分层：

1. **静态协议检查**：结构、版本、字段和地址是否合法；
2. **确定性策略检查**：权限、资源、速度、空间和状态机约束；
3. **语义监督**：意图与计划是否偏离、是否存在危险组合；
4. **人工确认**：高风险、歧义或无法自动恢复的动作。

只有较高层无法可靠处理的问题才升级，降低监督延迟和成本。

## 4. 机械臂安全边界

BusAgent 不是功能安全控制器。无论 Agent 如何规划，都必须由机器人控制栈提供独立保护：

- 急停与安全停机；
- 关节、速度、力矩和工作空间限制；
- 碰撞检测与人员安全区域；
- 轨迹验证和控制器状态反馈；
- 工具、负载和抓取约束；
- 通信丢失时的确定性安全状态。

Agent 层只能提交高层动作意图或经过约束的任务参数，不能跳过这些保护直接控制底层执行。

## 5. 人工确认策略

以下情况默认应确认或停止：

- 用户指代存在多个相近目标且置信度不足；
- 目标易碎、危险、贵重或可能属于他人；
- 动作路径进入人员附近或未观测区域；
- 当前设备状态与上下文记录不一致；
- 执行结果未知，重复动作可能造成伤害；
- 用户指令与安全策略冲突。

确认请求应具体展示目标、动作和风险，不只询问笼统的“是否继续”。确认也必须绑定任务版本，避免用户同意旧计划后误执行新计划。

## 6. 动态调整上下文与提示词

监督节点可以建议减少无关上下文、加入安全规则或切换提示词版本，但应遵循：

- 动态调整是带版本的配置变更，不是隐藏文本拼接；
- 变更只在声明的节点、任务或时间范围内有效；
- 权限和硬性安全规则不能由提示词覆盖；
- 调整前后都保留行为指标，支持回滚和评估；
- 用户输入和检索内容不能直接成为系统级规则。

## 7. 异常循环与滥用

总线应限制单条指令的最大派生深度、消息数量、模型预算和连续路由次数。发现节点互相反复投递、无进展重规划或持续调用高成本工具时，监督节点应暂停分支并输出可诊断原因。

## 8. 威胁模型起点

- 恶意或误导性的用户指令；
- 图像、网页、文档中的提示注入；
- 被攻陷或配置错误的节点；
- 伪造消息、重放和越权路由；
- 上下文仓库中的敏感数据泄露；
- 模型幻觉导致错误目标或动作；
- 消息拥塞导致安全事件被延迟；
- 观测系统记录过多敏感正文。

正式实现前需要针对具体部署环境完成独立威胁建模和安全评审。
