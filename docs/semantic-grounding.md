# 语义理解与物体相对移动

## 自然表达

生产配置的指令理解节点使用 Qwen 语义解析，输出受类型约束的意图和槽位，不再要求逐字匹配关键词。模型可通过节点配置中的 `model` 替换。停止/暂停仍保留快速确定性通道，不等待模型。

文本模型按职责分开：指令理解使用 `qwen3.8-flash`、`reasoning:low`；普通对话使用 `qwen-flash`、`reasoning:none`。两者在 `desktop-robot.app.json` 显式配置，优先于环境变量 `QWEN_CHAT_MODEL`。语音识别和语音合成模型不变。

语义请求发送 `enable_thinking:true`、`reasoning_effort:low`、temperature=0 与 JSON 输出模式；不同时设置 thinking_budget。输入历史只有已解析指令，因此关闭 preserve_thinking；思考内容不进入用户回复或语音。普通对话发送 `enable_thinking:false`，不发送 reasoning_effort。模型思考不保证语义永远正确。

`scripts/benchmark-chat-models.mjs` 用通用短问答测量模型接口首个正文 token 的延迟，不发送项目提示词。该数字不包含语音识别、语义分流及 TTS，不能当作端到端首字/首音延迟。普通聊天仍先经过语义节点，开启 low 推理会增加这一阶段的耗时。

聊天正文到达即发送 `reply.delta`，不再等待整段生成完成后做正则替换。事实性动作/感知播报仍由专门事件提供，普通聊天仍无执行工具；约束普通聊天措辞依赖现有提示词，流式播出内容不能事后撤回。思考内容仍不输出。

TTS 按 `robot.tts.config.chunk_chars=6`、`flush_ms=120` 合并小段，达到字数、标点或等待上限即提交；最后不足阈值的尾段在生成结束时提交。Qwen TTS 使用 commit 模式，分段按 response.done 串行调度以防音频交错；不等模型整句完成才开始合成。中断关闭连接并清空文字队列、定时器，前端停止已排队音频。6 字和 120 ms 是客户端提交阈值，不是保证首音延迟。短分段会牺牲一部分连贯语调。

`scripts/check-streaming-tts.mjs` 用通用测试文本验证真实音频在 finishTurn 之前返回，并验证后续片段继续输出；只计数 PCM，不保存、播放或操作机械臂。

提示词先解析最终肯定的意思，再选择操作部件，最后计算方向符号。停顿和口头改口不作为多个动作；否定的方向不采用。底座旋转为 `move_joint/shoulder_pan`，从上方俯视顺时针为正、逆时针为负；末端绕基座 Z 轴为 `rotate/frame:base`，使用右手定则。两者不能混用。完整新指令不继承旧动作类型，真正的补充句才补全历史槽位。

- “把机械臂复位”“回到最开始那个姿势” → home。
- “先把手张开” → 夹爪打开。
- “看看有没有黄色螺母” → 真实感知查询，不由对话模型生成场景结论。
- “让夹爪去刚才那个东西上面十公分处” → 最近明确物体 + 世界 Z 正方向 0.1 米。
- “向上挪五毫米” → 当前末端位置 + 世界 Z 正方向 0.005 米。

最近六次理解结果在同会话内保留两分钟，用于指代和参数补全。历史理解不代表执行成功；物体位置必须每次重新感知。缺参数则询问，模型不可用则明确未执行，不能退回闲聊承诺动作。多个动作先请用户分步下达。

## 物体定位链

指令理解提取物体、颜色、偏移 → Grounding 请求新观察 → 顶部 RGB-D 反投影 → 得到物体可见表面采样点 → 加上米制偏移 → 原有 IK/关节控制 → 实测到位反馈。

“物体上方10厘米”不等于“机械臂当前位置向上10厘米”。目前物体偏移按世界坐标：前后 X、左右 Y、上下 Z。“最左/最右”候选选择按顶部相机图像左右定义。位置来自有效物体像素的深度和相机标定，不使用旧的桌面像素线性映射，也不使用模型猜测或配置里的生成位置。

SO-101 仍受五轴运动学和工作空间限制。能理解和定位，不等于目标一定可达。此功能仍是位置约束 IK 与关节插值，不是直线避障、抓取或放置规划。

## 当前 Isaac 专用感知提供方

实测发现开放词汇检测器会把黄色螺母匹配成黄色螺栓，也可能为不存在的紫色五角星产生候选。因此当前提供方使用：

1. Florence/YOLOE 提供图像候选；
2. Isaac 相机语义分割核对候选物体类别；
3. RGB 颜色过滤和有效深度提取；
4. Isaac 相机标定接口反投影到世界坐标。

返回来源明确标记为 `scene_camera_rgbd+isaac_semantics`。这是利用仿真语义标注的定位能力，不能当作纯视觉模型的识别准确率，也不能原样宣称可用于无标注的真实摄像头。未标注物体、类别/颜色不符、缺深度、多候选、结果过期或中断都会停止该次定位移动，并说明原因。

HTTP `POST /api/ground` 接收 `category/color/selector/offset_m`，返回观察来源、物体点、偏移后目标点与时间戳。仅定位不执行。坐标目标随后走原有 `move_cartesian`。暂停会使等待中的语义/定位请求失效，防止旧请求延迟执行。

Web 只显示最近定位结果和坐标，不增加实时相机画面。

## 验证工具

- `BusAgent/backend/scripts/check-semantic-live.mjs`：只调用真实语义模型，不移动机器人。
- `tests/test_scene_grounding.py`：深度、类别/颜色、偏移、多候选、过期与中断测试。
- `BusAgent/backend/scripts/check-live-motion.mjs`：端到端语音后协议/文字协议检查；会驱动仿真机械臂，可传入待测句子。
