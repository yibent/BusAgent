# 路线图

路线图按风险验证顺序组织，不代表固定发布日期。每一阶段只有达到退出条件后才进入下一阶段。

## Phase 0：概念与协议设计

目标：统一术语、边界和最小协议，建立可讨论的架构基线。

- 明确消息身份、因果关系、流式分片和顺序作用域；
- 定义节点能力、并发、幂等和安全契约；
- 建立上下文分块与版本模型；
- 完成至少一个机械臂场景时序和故障分析；
- 识别需要 ADR 的未决技术选择。

退出条件：核心文档经过评审，关键术语无相互冲突，原型问题有可测量指标。

## Phase 1：最小总线原型

目标：仅验证消息路由、关联、并行与流式传递，不连接真实机械臂。

- 单进程或本地部署的最小消息总线；
- 节点注册与显式地址路由；
- 指令、消息、因果和 trace 标识；
- 两个并行消费者与一个流式消费者；
- 取消、超时、去重和基本背压；
- 可回放的结构化运行轨迹。

退出条件：在可重复测试中保持消息不串线，流式链路相较完整响应链路有明确首包延迟收益。

## Phase 2：模拟机械臂闭环

目标：在仿真环境验证规划、感知、用户确认和串行执行协调。

- 接入一个规划节点、一个对话节点和模拟感知节点；
- 建立带依赖和条件的任务图；
- 对机械臂资源实施串行租约与任务版本校验；
- 验证低置信度确认、取消、过期结果和未知执行结果；
- 加入确定性安全策略和监督节点。

退出条件：故障注入下不发生重复物理动作语义，旧任务结果不会推进新计划。

## Phase 3：上下文与监督评估

目标：验证按需上下文和去中心化路由是否带来质量、成本或安全收益。

- 上下文仓库的版本、权限和装配；
- 提示词、工具和路由策略版本追踪；
- 分层监督与人工确认；
- 异常循环和预算限制；
- 与单主 Agent 基线进行对照实验。

退出条件：在选定任务集上，至少一个核心指标显著改善，且监督拒绝、上下文泄露和任务错误处于预设阈值内。

## Phase 4：受控真实设备试验

目标：在隔离、受监督环境中连接真实设备，不面向无人值守生产使用。

- 通过机器人中间件适配器接入硬件；
- 使用独立控制器实施速度、空间、碰撞和急停限制；
- 建立执行凭证、状态查询和人工恢复流程；
- 完成安全评审、威胁建模和应急演练；
- 记录端到端延迟、成功率和用户纠正成本。

退出条件：由机器人、安全与系统负责人共同评审，确认下一阶段范围。

## Phase 5：可扩展生态

目标：在协议稳定后提供多语言 SDK、节点模板、适配器和能力目录。

此阶段的具体范围取决于前四阶段的数据，不提前承诺特定语言、消息中间件或模型供应商。

## 核心指标

| 维度 | 指标示例 |
| --- | --- |
| 延迟 | 首个用户反馈、首个计划、首个感知请求、任务总耗时。 |
| 正确性 | 消息串线、乱序、重复副作用、过期结果采用次数。 |
| 可靠性 | 超时恢复率、取消完成时间、节点故障降级率。 |
| 智能质量 | 任务成功率、工具选择正确率、用户纠正次数。 |
| 上下文效率 | 单节点 token、无关上下文比例、装配命中率。 |
| 安全 | 策略拒绝、人工升级、未授权访问和危险动作次数。 |
| 可运维性 | 单次指令可回放率、根因定位时间、版本可追踪率。 |

## 暂不承诺

- 在没有基准测试前承诺具体延迟倍数；
- 在没有真实安全评审前宣称可用于生产机械臂；
- 同时支持所有消息中间件、模型与机器人平台；
- 把小模型的工具调用成功率视为系统级可靠性保证。
